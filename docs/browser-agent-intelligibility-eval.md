# 浏览器 Agent 回答可理解度评测方案

## 1. 要解决什么问题

浏览器 Agent（Computer Use / Web Agent）经常把 **内部轨迹** 当成 **用户回答**：无障碍树、CSS 选择器、工具 JSON、未说明截图、base64、操作计划。任务可能做对了，用户却看不懂。

本方案只回答一个问题：

> **不看工具轨迹、不了解浏览器自动化的普通人，能否看懂智能体最终回答？**

它 **不是** 任务成功率评测。做成了但答得像日志，本方案判不合格；答得很清楚但事实错误，本方案可以判「人能看懂」，对错交给任务评测。

本仓库的可运行实现见 [`eval/intelligibility/`](../eval/intelligibility/README.md)。

## 2. 评测对象

| 评什么 | 不评什么 |
| --- | --- |
| 用户最终可见的终局回答 `final_answer` / `channel=user_visible` | 工具是否点对按钮 |
| 编码、语言、结构、结论是否可抽取 | 页面操作是否成功 |
| 轨迹是否泄漏进用户正文 | 幻觉、安全、越权（另开专项） |
| 截图有没有文字解释 | 截图像素是否正确 |

建议按 **目标浏览器 × 场景** 切片，例如 Chromium / Chrome / Edge；场景至少覆盖：搜索、抽取、表单、登录后操作、购物/下单、多步对比。

## 3. 三级判定（报告主列）

报告第一列必须是 **「人能看懂吗」**，不要只给 0–100 分。

| 判定 | 分数 | 定义 | 普通人 10 秒后 |
| --- | ---: | --- | --- |
| **人能看懂** `readable` | ≥ 75 | 自然语言或清楚的列表/表格，结论靠前 | 能复述结论 |
| **部分能看懂** `partial` | 45–74 | 有结论，但夹杂 dump、术语、超长原文、语言别扭 | 要挑拣才能找到答案 |
| **人看不懂** `unreadable` | < 45 | 乱码、空答、纯机器日志、纯截图、只说下一步 | 无法当作回答 |

机器可读 ≠ 人能看懂。一整段 `{"temp":21}` 对程序友好，对本方案仍是「人看不懂」或最多「部分能看懂」。

## 4. 八个维度

权重写在 [`eval/intelligibility/rubric.json`](../eval/intelligibility/rubric.json)。

1. **表面完整**（15%）：无乱码、替换符、二进制、明显截断。
2. **面向用户**（20%）：正文是给人的答案，不是内部 trace。
3. **自然语言**（15%）：完整句子或小标题，不是选择器/角色树/函数调用。
4. **结论可抽取**（20%）：10 秒内能找到任务结论；关键数字靠前。
5. **轨迹隔离**（12%）：工具调用、a11y 树、原始 HTML/JSON 不进用户正文。
6. **视觉可解释**（8%）：截图有说明；禁止「只丢一张图」。
7. **认知负担**（5%）：不是一面墙日志。
8. **任务相关**（5%）：在回答用户的问题，而不是只汇报点了什么。

## 5. 失败类型（必须打到原文上）

| 代码 | 含义 | 典型原文 |
| --- | --- | --- |
| `EMPTY` | 空回答或占位符 | `（空）` / `TODO` |
| `ENC` | 乱码 | `ä»Šå¤©åŒ—äº¬` |
| `TRACE` | 工具日志当回答 | `browser_click(#submit)` |
| `DOM` | 无障碍树 / HTML dump | `[button] Search` / `html > body > div` |
| `JSON` | 原始载荷当回答 | `{"tool_call":...}` |
| `SCREEN` | 截图无文字解释 | 只有 screenshot，caption 为空 |
| `PLAN` | 只宣布下一步 | 「我将点击搜索按钮」 |
| `MIX` | 结论被日志淹没 | 一句人话 + 大段 JSON |
| `LANG` | 语言不对或界面字符串堆砌 | 中文提问，整页英文 UI 词堆砌 |
| `WALL` | 超长无结构 | 把整页 innerText 贴回用户 |

报告必须 **高亮这些片段**，不能只给分数。这就是「暴露智能体回答的内容是否是人能看懂」。

## 6. 评测流程

```text
采集轨迹（目标浏览器）
        │
        ▼
归一化 transcript（分开 user_visible / trace）
        │
        ├─► 启发式闸门（空答、乱码、DOM/JSON/工具 dump、计划-only）
        ├─► 可选 LLM Judge（只看终局回答，不看是否做对）
        └─► 不一致 → 标 needs_human_review，发布门禁用更严的一档
        │
        ▼
报告：人能看懂吗 + 原文 + 失败高亮 + 门槛
```

原则：

- **先暴露原文，再打分。** 没有原文的评测无效。
- **启发式高召回抓「不像人话」**，LLM Judge 处理擦边（啰嗦但可读、中英夹杂但仍能懂）。
- **有结论但轨迹泄漏，最高只能「部分能看懂」。**
- **空答、乱码、纯 dump、纯截图、计划-only，直接「人看不懂」。**

## 7. 样本怎么采

每个目标浏览器至少：

| 桶 | 最低条数 | 目的 |
| --- | ---: | --- |
| 金样（应「人能看懂」） | 20 | 防止把正常回答打成不可读 |
| 脏样（应「人看不懂」） | 20 | DOM dump、JSON、乱码、空答、计划-only |
| 擦边（应「部分能看懂」） | 15 | 结论 + 泄漏、语言别扭、过长 |
| 真实在线任务 | 30+ | 按搜索/抽取/表单/交易分层 |

轨迹字段最小集：`run_id`、`agent`、`target.browser`、`user_query`、`final_answer`、`messages[].channel`。ChatGPT Web 本地会话可直接导入。

## 8. LLM Judge 协议（可选）

Judge **只看** 用户问题和终局回答，**不要**把整段 a11y 树喂进去当「答案」。系统提示见 `eval/intelligibility/lib/judge.mjs`。

输出必须是 JSON：`verdict` / `score` / `human_can_understand` / `reason` / `failures[]`。

与启发式不一致时：

1. 报告同时保留两个结果；
2. 发布门采用更差的一档；
3. 计入人工抽检队列。

不要用「任务成功」的 Judge 提示词来评可理解度，否则会把「做对但答成日志」误判为通过。

## 9. 报告规范（强制）

一份合格报告必须能让评审 **直接看见智能体说了什么**。

1. 封面 KPI：人能看懂 / 部分能看懂 / 人看不懂 的占比、平均分、是否过发布门槛。
2. 总表列顺序：`人能看懂吗` → 分数 → run_id → 场景 → 失败代码。
3. 每条样本展开：
   - 用户问题原文
   - **智能体终局回答全文**（不要只给摘要）
   - 失败类型高亮
   - 八维分数
   - 内部轨迹仅作折叠附录
4. 失败类型直方图，便于改 Agent 的输出层而不是乱调模型。

本工具默认写出 `report.html`、`report.md`、`report.json`。HTML 是给人审的主报告。

## 10. 发布门槛

默认（可在 `rubric.json` 调整）：

- **人能看懂** ≥ 85%
- **人看不懂** ≤ 5%
- 启发式与 Judge 不一致的样本必须人工复核后才能算通过

建议按浏览器分别出报告，不要把 Chromium 实验室结果直接当成 Edge 实网结果。

## 11. 和产品落地的关系

浏览器 Agent 的输出层应强制：

1. 对用户只发 `user_visible` 终局文字；
2. 工具调用、DOM、截图二进制留在 trace；
3. 终局模板：**结论先行** → 依据（可选短引用）→ 下一步建议；
4. 有截图必须配一句说明；
5. 禁止把 `function_call` JSON 或 a11y 树渲染进聊天气泡。

本仓库聊天界面若接入浏览器 Agent，应用同一套闸门：上线前跑本评测，气泡里只渲染通过「面向用户」检查的内容。

## 12. 落地顺序

1. 冻结本方案的三级判定和失败代码（已写入 `rubric.json`）。
2. 用夹具跑通报告：`node eval/intelligibility/cli.mjs`。
3. 接入真实 Agent 轨迹（或 ChatGPT Web 导出会话）。
4. 对「人看不懂」Top 失败类型改输出协议，而不是先换模型。
5. 需要擦边语义时再开 `--judge`。
6. 每个目标浏览器出一份独立 HTML 报告，作为发布附件。

## 13. 反例（方案要挡住的）

| 用户问题 | 错误终局 | 应判 |
| --- | --- | --- |
| 今天北京天气？ | `[combobox] Search` … | 人看不懂 / DOM |
| 购物车多少钱？ | `{"tool_call":"click"}` | 人看不懂 / JSON |
| 这个标题是什么？ | 一张无 caption 截图 | 人看不懂 / SCREEN |
| 会下雨吗？ | 「我将点击搜索」 | 人看不懂 / PLAN |
| 合计多少？ | 「¥128」+ 整页 a11y 树 | 部分能看懂 / MIX |

对应夹具在 `eval/intelligibility/fixtures/`。
